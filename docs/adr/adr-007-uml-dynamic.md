# ADR-007. Динамическое поведение моделируется на UML в нотации PlantUML

- **Статус:** принято
- **Дата:** 2026-11-09
- **Связанные требования:** SRS 0.2 целиком; задание ЛР5

## Контекст

Нужно описать поведение PriceRadar: кто и что делает с системой, в каком порядке и как меняются состояния объектов. Структура уже описана в SDD (представления 001–013), динамика — частично (007, 009). Документы живут в git и проходят ревью.

## Варианты

- **PlantUML** — текст, версионируется, есть дорожки активности, составные состояния, история, `create`/`destroy`.
- **Mermaid** — уже используется для C4 в SDD, но нет дорожек в диаграмме активности и слабая поддержка состояний с историей.
- **Графический редактор (draw.io, Visual Paradigm)** — быстро рисовать, но бинарные файлы не сравниваются в diff.

## Решение

Выбран PlantUML для всех диаграмм динамики: исходники `docs/uml/diagrams/*.puml`, изображения `docs/uml/img/*.png` создаются из исходников. Mermaid остаётся для C4 и компонентов.

## Последствия

- (+) Изменения диаграмм видны в diff, ревью как у кода.
- (+) Единый стиль нотации.
- (−) Нужна Java или плагин для генерации PNG; в CI добавляется шаг сборки.

## Механизмы построения диаграмм

1. **События внешнего мира → актёры.** Перечисляются события, на которые отвечает система (действие пользователя, срабатывание времени, ответ внешней системы); их источники становятся актёрами.
2. **Требования → прецеденты.** Каждое функциональное требование SRS отдаётся одному или нескольким прецедентам; общие шаги выносятся через include, условные ветви — через extend.
3. **Потоки событий → активность.** Шаг основного потока — действие, альтернативный поток — ветка решения, участник — дорожка.
4. **Перечисления данных → состояния.** Состояния берутся из полей модели данных (статус товара, алерта, ссылки), события переходов — из вызовов методов и прецедентов.
5. **Модули SDD → линии жизни.** Участники диаграмм последовательности — модули и классы из представлений 002 и 004; стереотипы: boundary, control, entity, database.

## Механизмы связи между диаграммами

- **Сквозные идентификаторы:** REQ-… → UC-NN → файл диаграммы (номер и имя в `diagrams/`) → представление SDD → ADR. Идентификатор указан в заголовке диаграммы и в «More Information».
- **Единые имена:** название прецедента, действия на диаграмме активности и сообщения на диаграмме последовательности совпадают с текстом потока событий.
- **Единые значения:** состояния и переходы автоматов согласованы с перечислениями в представлении 005 и правилами представления 008.
- **Проверка:** в CI проверяется, что каждый `UC-NN` из `use-cases.md` встречается в трассировке SDD 5.1, а `.puml` собирается без ошибок.
